    #Behaviors

    #switchActuator/v1

    Switch actuator: each channel drives a relay; optional timer, status feedback, and power and energy metering. Output command: switch.

    Ports

    Port DPT Channel Role
    switch 1.001 required Switching command of the output (0 = off, 1 = on).
    status 1.001 required Status of the relay, sent after each effective change.
    scene 17.001, 18.001 optional (all channels when omitted) scene number (17.001), or scene control (18.001) whose learn bit stores the current state
    forced 2.001 required Priority override (2 = force off, 3 = force on, 0 or 1 = end of the override).
    lock 1.001 required 1 locks the output in the state set by lockStart, 0 unlocks it (afterLock)
    logic 1.001 required combined with the switching command by logicOperation (AND or OR)
    power 14.056, 9.024 required electrical power drawn by the load of the channel: W with 14.056, kW with 9.024
    energy 13.010, 13.013 required active energy counted for the channel, sent cyclically: Wh with 13.010, kWh with 13.013
    totalPower 14.056, 9.024 none sum of the power of all channels: W with 14.056, kW with 9.024
    powerLimit 1.005, 1.001 none 1 when the total power reaches powerLimitW, 0 after hysteresis (load shedding)
    intrusionAlarm 1.005, 1.001 optional (all channels when omitted) 1 makes the output blink and ignore the commands; 0 ends the alarm (afterAlarm). Without channel, applies to all channels.
    fireAlarm 1.005, 1.001 optional (all channels when omitted) 1 forces the output on and ignores the commands, with priority over intrusion; 0 ends the alarm. Without channel, applies to all channels.

    Device parameters (parameters)

    Parameter Type Default Constraints Description
    meterIntervalMs integer 5000 ≥ 1000 Cyclic sending of power and energy values (ms), for channels with metering objects.
    powerSendDeltaW number 10 ≥ 0 Send a power value when it changes by at least this many watts.
    energyTimeScale number 60 > 0 Energy counting speed: 60 counts one simulated second as one minute, so that the counter moves visibly; 1 counts real time.
    powerLimitW number 0 ≥ 0 Total power (W) of the actuator outputs at which the powerLimit object is set, for load shedding (0 disables it).
    sheddingTimeMs integer 20000 ≥ 0 A shed output is switched on again after this time, if its command still requests it; it is shed again if the limit is still exceeded.
    powerLimitHysteresisW number 50 ≥ 0 The powerLimit object is reset below limit − hysteresis (W).

    Channel parameters (channels[].parameters)

    Parameter Type Default Constraints Description
    timerMs integer null null > 0
    timerRetrigger string "restart" "restart" (Restarts), "none" (No effect), "add" (Extends) When 1 is received during a timer: restart begins a full period, none ignores it, and add extends the period (up to five times).
    timerWarningMs integer 0 ≥ 0 Time before the timer ends when the output briefly opens for one second as a warning (0 disables the warning).
    timerOffAllowed boolean true Allow a 0 write to switch off before the timer ends; otherwise ignore it.
    loadShedding boolean false Switch this output off while the total power limit of the actuator is exceeded (load shedding).
    relayMode string "normallyOpen" "normallyOpen" (Normally open), "normallyClosed" (Normally closed) normallyOpen closes the contact when the channel is on; normallyClosed closes it when the channel is off, so the load is powered while the switching state is 0. Status feedback reports the switching state, not the contact.
    statusDelayMs integer 300 ≥ 0 Delay before sending status feedback (ms).
    onDelayMs integer 0 ≥ 0 Delay between a 1 on the switching object and switching on (0: at once). A 0 received meanwhile cancels it; scenes, forcing, and the lock act at once.
    offDelayMs integer 0 ≥ 0 Delay between a 0 on the switching object and switching off (0: at once). A 1 received meanwhile cancels it.
    lockStart string "unchanged" "unchanged" (Unchanged), "on" (On), "off" (Off) State of the output when the lock object receives 1; while locked, commands are stored without effect. Forcing has priority over the lock.
    afterLock string "lastCommand" "lastCommand" (Last command), "previous" (Previous state), "unchanged" (Unchanged), "on" (On), "off" (Off), "toggle" (Toggle) State when the lock object receives 0: follow the latest command received while locked, restore the state before the lock, keep the current state, switch on, switch off, or invert.
    logicOperation string "and" "and" (AND: on when the command and the logic object are 1), "or" (OR: on when the command or the logic object is 1) Combination of the switching command with the logic object (for example an enable from a presence detector). Until the logic object receives a value, the command acts alone.
    sceneLearning boolean true A scene control telegram with the learn bit (DPT 18.001) stores the current state of the output as the scene; it replaces the configured preset until the simulation restarts.
    busFailure string "unchanged" "unchanged" (Unchanged), "off" (Off), "on" (On) State of the output when the bus voltage fails; the relay is then left as it is until the voltage returns.
    busRecovery string "previous" "previous" (State before the failure), "off" (Off), "on" (On) State of the output when the bus voltage returns; the status feedback is then sent.
    blinkMs integer 1000 ≥ 1000 Time the contact stays closed, then open, while the intrusion alarm makes the output blink; mind the switching life of the relay.
    afterAlarm string "lastCommand" "lastCommand" (Last command), "previous" (Previous state), "unchanged" (Unchanged), "on" (On), "off" (Off) State when the last alarm (fire, intrusion) ends: follow the latest command received during the alarm, restore the state before it, keep it on, switch on, or switch off.
    forcedReleaseMs integer 0 ≥ 0 Time after which a forcing ends by itself, counted from its last forcing telegram, as if a release telegram had arrived (0: only a release telegram ends it). Actuators offer up to several hours.
    afterForcing string "lastCommand" "lastCommand" (Last command), "previous" (Previous state), "unchanged" (Unchanged), "on" (On), "off" (Off), "toggle" (Toggle) State after a priority override ends: follow the latest command received during the override, restore the previous state, keep the forced state, switch on, switch off, or invert the forced state.

    Initial channel state (channels[].initialState)

    Parameter Type Default Constraints Description
    on boolean false Switching state of the channel when the simulation starts.

    #shutterActuator/v1

    Shutter actuator without sensor: position estimated from the configured travel time. Output command: motor.

    Ports

    Port DPT Channel Role
    move 1.008 required Up/down: 0 raises toward 0 %, 1 lowers toward 100 %.
    stopStep 1.007 required Stop when moving; otherwise one step of stepPct (0 up, 1 down).
    positionCommand 5.001 required Target position in percent.
    positionStatus 5.001 required Estimated position, sent after stopping.
    scene 17.001, 18.001 optional (all channels when omitted) scene number (17.001), or scene control (18.001) whose learn bit stores the current position
    slatCommand 5.001 required slat angle (0 % open, 100 % closed) of a venetian blind
    slatStatus 5.001 required estimated slat angle, sent after stopping
    windAlarm 1.005, 1.001 optional (all channels when omitted) 1 starts the wind alarm (windReaction, up by default): commands are ignored until 0; without channel, applies to all channels
    lock 1.001 required 1 locks the output: commands are ignored, with the reactions lockStart and afterLock; by default, weather alarms keep priority (safetyPriority).
    rainAlarm 1.005, 1.001 optional (all channels when omitted) 1 starts the rain alarm (rainReaction); 0 ends it
    frostAlarm 1.005, 1.001 optional (all channels when omitted) 1 starts the frost alarm (frostReaction); 0 ends it
    forced 2.008, 2.001 required 3 forces down, 2 forces up; 0 or 1 ends the forcing (afterForcing). By default, weather alarms and the lock keep priority (safetyPriority).
    recallPosition12 1.022, 1.001, 1.002 required 0 moves to the stored position 1, 1 to the stored position 2
    recallPosition34 1.022, 1.001, 1.002 required 0 moves to the stored position 3, 1 to the stored position 4
    storePosition12 1.001, 1.002 required 0 stores the current position as position 1, 1 as position 2
    storePosition34 1.001, 1.002 required 0 stores the current position as position 3, 1 as position 4
    upperLimit 1.002, 1.001 required 1 when the shutter is estimated at the top (0 %), sent on change
    lowerLimit 1.002, 1.001 required 1 when the shutter is estimated at the bottom (100 %), sent on change

    Channel parameters (channels[].parameters)

    Parameter Type Default Constraints Description
    estimatedTravelTimeMs (required) integer > 0 Travel time configured in the actuator (ms): downwards, and upwards unless estimatedTravelTimeUpMs is set.
    estimatedTravelTimeUpMs integer > 0 Upward travel time configured in the actuator (ms), when it differs from the downward time; many actuators take separate times because a shutter rises more slowly than it falls.
    startDelayMs integer 300 ≥ 0 Delay before starting or reversing motion (ms).
    statusDelayMs integer 300 ≥ 0 Delay before sending position feedback (ms).
    slatTravelMs integer 0 ≥ 0 Venetian blind: time configured for the slats to turn from open to closed (ms). A movement first turns the slats; a short press at rest turns them by slatStepPct. 0 for a roller shutter without slats.
    slatStepPct number 20 ≥ 1 ; ≤ 100 Slat angle change for a short press at rest (%).
    stepPct number 0 ≥ 0 ; ≤ 100 Position step for a stop/step command received at rest by a shutter without slats (%). 0 (default): no movement, as in the KNX stop/step function, where the step turns slats; some actuators move a roller shutter by this amount instead.
    endSupplementPct number 0 ≥ 0 ; ≤ 50 Extra travel time toward 0% or 100%, as a percentage of full travel. The motor runs even if the estimate is already at the limit; the end stop recalibrates the estimate (often 5–10% on a real actuator).
    invertOutput boolean false Invert the up and down outputs to compensate a motor wired in reverse (shutter parameter wiringReversed). Without such wiring, enabling it makes the shutter move opposite to the commands.
    sceneLearning boolean true A scene control telegram with the learn bit (DPT 18.001) stores the current estimated position as the scene; it replaces the configured preset until the simulation restarts.
    windReaction string "up" "up" (Up), "down" (Down), "stop" (Stop), "none" (No movement) Movement when the wind alarm starts; commands are then ignored until it ends.
    rainReaction string "up" "up" (Up), "down" (Down), "stop" (Stop), "none" (No movement) Movement when the rain alarm starts (an awning or a blind is usually raised).
    frostReaction string "none" "up" (Up), "down" (Down), "stop" (Stop), "none" (No movement) Movement when the frost alarm starts; a frozen shutter is usually left where it is.
    alarmPriority string "wind,rain,frost" "wind,rain,frost" (Wind > Rain > Frost), "wind,frost,rain" (Wind > Frost > Rain), "rain,wind,frost" (Rain > Wind > Frost), "rain,frost,wind" (Rain > Frost > Wind), "frost,wind,rain" (Frost > Wind > Rain), "frost,rain,wind" (Frost > Rain > Wind) Order of the weather alarms when several are active: the first one active applies.
    safetyPriority string "alarms,lock,forced" "alarms,lock,forced" (Weather alarms > Lock > Forcing), "alarms,forced,lock" (Weather alarms > Forcing > Lock), "lock,alarms,forced" (Lock > Weather alarms > Forcing), "lock,forced,alarms" (Lock > Forcing > Weather alarms), "forced,lock,alarms" (Forcing > Lock > Weather alarms), "forced,alarms,lock" (Forcing > Weather alarms > Lock) Order of the weather alarms, the lock, and forcing when several are active: the first one active holds the output, and commands are ignored.
    alarmMonitoringMs integer 0 ≥ 0 Weather sensors send their alarm cyclically: without a telegram on an alarm object within this time, the alarm is assumed (0: no monitoring).
    afterAlarm string "none" "none" (No movement), "up" (Up), "down" (Down), "restore" (Position before the alarm) Movement when the last weather alarm ends.
    afterForcing string "none" "none" (No movement), "up" (Up), "down" (Down), "restore" (Position before the forcing) Movement when the forcing ends (0 or 1 on the forcing object).
    preset1Pct number 20 ≥ 0 ; ≤ 100 Position recalled by 0 on the object of positions 1/2.
    preset2Pct number 40 ≥ 0 ; ≤ 100 Position recalled by 1 on the object of positions 1/2.
    preset3Pct number 60 ≥ 0 ; ≤ 100 Position recalled by 0 on the object of positions 3/4.
    preset4Pct number 80 ≥ 0 ; ≤ 100 Position recalled by 1 on the object of positions 3/4.
    presetStoring boolean true The store objects replace a stored position with the current estimated position, until the simulation restarts.
    lockStart string "none" "none" (No reaction), "up" (Up), "down" (Down), "stop" (Stop), "position" (Position) Movement when the lock object receives 1; the wind alarm keeps priority.
    lockPositionPct number 0 ≥ 0 ; ≤ 100 Position reached when the lock starts, with “Position”.
    afterLock string "none" "none" (No reaction), "up" (Up), "down" (Down), "restore" (Position before the lock) Movement when the lock object receives 0.
    busFailure string "stop" "stop" (Stop), "up" (Up), "down" (Down) Motor when the bus voltage fails: stopped, or driven toward an end position until the voltage returns; the estimated position follows the time elapsed.
    busRecovery string "none" "none" (No movement), "up" (Up), "down" (Down), "position" (Position) Movement when the bus voltage returns; the estimated position is sent in any case.
    busRecoveryPositionPct number 0 ≥ 0 ; ≤ 100 Position reached on bus recovery, with “Position”.

    Initial channel state (channels[].initialState)

    Parameter Type Default Constraints Description
    estimatedPositionPct number 0 ≥ 0 ; ≤ 100 Position the actuator assumes at start (0 = fully open, 100 = fully closed); the connected shutter starts at its own position.
    estimatedSlatPct number 0 ≥ 0 ; ≤ 100 Slat angle the actuator assumes at start (venetian blinds).

    #presenceDetector/v1

    Presence detector: sends 1 on first detection, 0 when its hold time ends (restarted by each detection). Uses buttons and inputs.

    Ports

    Port DPT Channel Role
    input 1.001, 1.018 none output object: 1 on detection, 0 when the timer expires
    lock 1.001 none 1 locks the detector: its detections (and those of its slaves) are ignored; 0 unlocks it
    slaveTrigger 1.001, 1.018 none 1 sent by a slave detector of the same room: counts as a detection (master/slave operation)
    brightness 9.004 none measured brightness (lx), entered by the reader and sent; there is no light model

    Device parameters (parameters)

    Parameter Type Default Constraints Description
    lockStart string "none" "none" (No telegram), "off" (Off), "on" (On) Telegram when the lock object receives 1: none (the hold time runs out as usual), 0 at once, or 1 kept while locked. While locked, detections are ignored.
    lockEnd string "none" "none" (No telegram), "off" (Off), "on" (On) Telegram when the lock object receives 0: none, 0, or 1 followed by the hold time.
    slave boolean false Sends 1 to the slaveTrigger object of a master detector of the same room, at the first detection and then every slaveCyclicMs while its own hold time runs; the master keeps the brightness threshold, the final 0, and its hold time after the last 1.
    slaveCyclicMs integer 3000 ≥ 0 Interval at which a slave detector repeats 1 while its hold time runs; shorter than the hold time of the master. Manufacturers suggest about 30 s, compressed here like the hold times. 0: no repetition, the slave sends 1 at each detection instead.
    holdMs integer 10000 > 0 Time with no detected presence before sending 0 (ms); restarted on each detection.
    retrigger boolean true Each activation restarts the timer; otherwise it runs from the first activation.
    sendOnEnd boolean true Send 0 when the timer expires; otherwise the detector sends only 1 and the actuator handles switch-off.
    brightnessThresholdLux number 0 ≥ 0 A detection switches on only while the entered brightness is below this value (lx); an active presence is still extended. 0 disables the threshold.

    #roomThermostat/v1

    Room thermostat: comfort / standby / economy / protection modes (20.102), window and presence, PI control (5.001 or PWM) or two-point, heating and cooling. Uses buttons and inputs.

    Ports

    Port DPT Channel Role
    actualTemp 9.001 none Measured temperature (9.001), sent on change.
    sensorFault 1.005, 1.001 none 1 when no temperature is usable (external temperature too old and no room sensor); 0 when one comes back
    externalTemp 9.001 none replaces the internal sensor after a value is received
    baseSetpoint 9.001 none Base comfort setpoint for heating (9.001).
    setpointShift 9.002 none base setpoint = configured setpoint + offset
    setpointStatus 9.001 none Current setpoint (9.001).
    hvacMode 20.102 none Selected mode (20.102: 0 auto, 1 comfort, 2 standby, 3 economy, 4 protection).
    comfortMode 1.001 none 1 selects comfort, which has priority over night; with the other 1-bit mode objects, replaces the 1-byte preselection
    nightMode 1.001 none 1 selects night (economy), 0 standby, unless comfort or protection is 1
    protectionMode 1.001 none 1 selects frost or heat protection, which has priority over comfort and night
    forcedMode 20.102 none 1–4 forces comfort, standby, economy, or protection over everything else, the window included; 0 (auto) ends the forcing
    hvacModeStatus 20.102 none Current mode (20.102).
    presence 1.018, 1.001 none 1 = presence: comfort mode
    window 1.019, 1.001, 1.009 none open window (1.019 / 1.001: 1 = open; 1.009: 0 = open): protection mode, over everything but the forced mode
    heatCool 1.100 none 1 = heating, 0 = cooling; not used with the automatic change-over
    heatCoolStatus 1.100 none Current mode: 1 heating, 0 cooling (1.100).
    heatingValue 5.001 none continuous control value from 0 to 100%
    heatingSwitch 1.001 none two-point control, or PWM under PI control
    coolingValue 5.001 none Continuous cooling control value (5.001).
    coolingSwitch 1.001 none One-bit cooling command.
    controlValue 5.001 none control value of the active mode, heating or cooling, on one object (2-pipe system); heatCoolStatus tells which
    controlSwitch 1.001 none one-bit control of the active mode, heating or cooling, on one object (2-pipe system)

    Device parameters (parameters)

    Parameter Type Default Constraints Description
    presenceType string "detector" "detector" (Presence detector), "button" (Presence button) detector: comfort while the presence object is 1; button: each 1 extends the comfort mode for comfortExtensionMs.
    comfortExtensionMs integer 7200000 ≥ 60000 Duration of the comfort mode started by the presence button (2 h by default).
    changeover string "object" "object" (By the heating / cooling object), "automatic" (Automatic) object: the heatCool object (1.100) selects heating or cooling, for example from a central change-over or the water supplied in a 2-pipe system; automatic: the thermostat cools above the cooling setpoint and heats below the heating setpoint, the dead zone in between.
    controlType string "pi" "pi" (PI (continuous or PWM)), "twoPoint" (Two-point) pi uses proportional-integral control with a continuous value (5.001) or PWM (1 bit); twoPoint uses on/off control with hysteresis.
    comfortC number 21 ≥ 5 ; ≤ 35 Initial heating comfort setpoint (°C); the baseSetpoint object can replace it.
    standbyShiftK number 2 ≥ 0 ; ≤ 10 Standby setpoint offset (K): lower for heating, higher for cooling.
    economyShiftK number 4 ≥ 0 ; ≤ 15 Economy or night setpoint offset (K): lower for heating, higher for cooling.
    frostProtectionC number 7 ≥ 3 ; ≤ 15 Heating setpoint in protection mode (°C).
    heatProtectionC number 35 ≥ 25 ; ≤ 45 Cooling setpoint in protection mode (°C).
    deadZoneK number 3 ≥ 0 ; ≤ 10 Difference between heating and cooling comfort setpoints (K), for example 21 °C and 24 °C.
    minSetpointC number 5 ≥ 0 ; ≤ 30 Lowest base setpoint accepted (°C); lower received or entered values are raised to it.
    maxSetpointC number 35 ≥ 10 ; ≤ 50 Highest base setpoint accepted (°C); higher received or entered values are lowered to it.
    hysteresisK number 0.5 ≥ 0.1 ; ≤ 5 Two-point control switches on again when temperature differs from the setpoint by this amount (K).
    proportionalBandK number 2 ≥ 0.5 ; ≤ 10 Temperature difference (K) that produces 100% output from the proportional term.
    integralTimeMs integer 120000 ≥ 0 PI integral time: a constant error doubles the proportional response after this duration (0 selects P control). Real installations use 60–240 minutes; the default follows compressed simulated room time.
    pwmCycleMs integer 20000 ≥ 1000 PWM cycle period for a 1-bit control object (real installations typically use 10–20 minutes).
    controlPeriodMs integer 1000 ≥ 100 Interval at which the controller recalculates its control value from the measured temperature.
    valueSendDeltaPct number 5 ≥ 1 ; ≤ 50 Send the control value when it changes by at least this many percentage points.
    sensorFaultValuePct number 0 ≥ 0 ; ≤ 100 Control value sent when no temperature is usable (external temperature too old, no room sensor), until a temperature comes back.
    externalTempTimeoutMs integer 0 ≥ 0 If no externalTemp value arrives within this time, control uses the internal sensor again until a new value arrives (0 disables monitoring).
